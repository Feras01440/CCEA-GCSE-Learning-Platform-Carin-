# Cairn — developer notes

A private CCEA GCSE study platform (Mathematics, Further Mathematics, Double Award Science). Static Next.js 16 export, all learner data in the browser (IndexedDB), no accounts, no backend.

## Run

```bash
npm install
npm run dev            # http://localhost:3000 (the in-app preview uses port 3017)
npm run build          # content + decks build, static export to out/, RSC payload fix (scripts/fix-export.mjs), service worker
npx serve out          # serve the export locally
npm test               # vitest
```

Windows: use Git Bash or `npm.cmd`; keep the folder excluded from Defender scanning for faster file watching.

## Content rules

- Learn from sources, never copy them. CCEA papers are deep-linked, never re-hosted (their site blocks iframes). Corbettmaths and Bitesize are linked with credit.
- Every item carries a verification log; only `verified`/`published` items ship (`pipeline/build-content.mts`).
- Bundle `topic.slug` must equal the taxonomy slug in `data/spec/<subject>.json` so the app can find it.
- Grades are A*–G with C*; UMS is the truth; A* is shown as a band.

## Marking rules authors rely on

- Text key words (`src/components/items/text-marking.ts`): matched as whole words or phrases after lower-casing and dropping punctuation and apostrophes (Benedict's = benedicts). A phrase may take a trailing s/es; a single word of 4+ letters also matches its inflections from a closed list of endings (denatur → denatured / denaturation, heat → heated, increase → increasing) but never an unrelated longer word (cell ≠ cellulose, ratio ≠ rational). The first entry of each group is what the "still missing …" feedback prints, so make it a real word. An algebraic key word (one carrying a digit and an operator, such as "(2x - 1)(x + 3) = 30" or "2x^2 + 5x - 33 = 0") is matched with the spaces around + - / ^ * ignored on both sides, and a typed ² or ³ reads as ^2 or ^3, so one spelling per working line is enough: no spacing or superscript variants. A hyphen joining plain words is a space ("nitrogen-fixing" = "nitrogen fixing", "y-intercept" = "y intercept"), so one spelling per compound is enough too; a token with a digit or another operator ("2a-b") keeps its minus. `npm run content:check` prints a `KEYWORDS` line for any group no accepted answer can earn (`src/components/items/keyword-lint.ts`); the count is in the summary line and is not fatal.
- Key-word groups are presence-based: an "assign A/B/C" part written as one text answer cannot detect a swapped assignment. Split such parts into sub-parts. A key word earns one group only, so "give two of …" written as two groups with the same list needs two different items. Currency and percent signs are dropped before matching ("£8106.96" earns "8106.96"). Never use a bare "A"/"a" as a key word: it matches the article.
- Coordinate-pair specs (an algebraic spec whose latex is tuples) may use LaTeX (`\sqrt{2}`, `\frac{1}{2}`); the learner may type tuples or "x = …, y = …" in any order. An optional `tolerance` (absolute, per coordinate) lets a rounded pair earn an exact one ("(0.83, -3.08)" for (5/6, −37/12) with `tolerance: 0.01`); without it the match is exact.
- `matrix` answers (Further Maths Unit 1: sums, differences, scalar multiples, products, the identity and inverses of 2×2 matrices) are typed into a grid of entry boxes (`src/components/items/MatrixField.tsx`) and marked entry by entry, in place (`src/lib/marking/matrix.ts`). The spec is `{ kind: "matrix", rows, cols, entries }` with `entries` as `rows` rows of `cols` strings, each a number or a short algebraic expression ("5", "-3", "1/2", "2a", `\frac{1}{2}`); an optional `tolerance: { type: "absolute", value }` lets a rounded entry earn an exact one, and without it every entry must be the value as written. An entry of digits goes to the numeric engine and an entry carrying a letter or a TeX command to the algebra engine's equivalence, so "0.5", "1/2" and `\frac{1}{2}` are one answer. She may write the matrix as a `pmatrix` / `bmatrix` / `vmatrix` / `matrix` environment, as a nested list (`[[1,2],[3,4]]`, `((1,2),(3,4))`), or as the plain grid the field submits (`1 2; 3 4` — rows on new lines or after ";", entries separated by spaces or commas), with the matrix named in front if she likes ("AB = …"). The field also offers a box in front of the brackets for a scalar ("1/5"), which the marker multiplies into every entry, so a stem may say a fraction in front of the brackets is accepted. The part's marks are shared in proportion, so three entries of four on a 2-mark part is 1 mark; an answer that is the transpose is named as the transpose and keeps only the entries the swap left where they were; an answer of the wrong size earns nothing and is asked for again at the right size. A matrix answer carries no unit. Write a matrix common error as the whole wrong matrix, `pattern: { kind: "matrix", entries: [["1", "8"], ["0", "-3"]] }`, which fires when every entry agrees (the same spelling, or the same number); a text pattern on a matrix part is matched against the plain grid ("1 2; 3 4"). Never encode a matrix as a `table` with one cell per entry: cells carry no shape, so a transposed answer would earn full marks, and no matrix common error could be written. `npm run content:check` is fatal on a matrix whose `entries` do not fill its rows × cols, and on a matrix common error equal to the answer.
- `graph` answers with plot "transformation" are drawn on an interactive grid (`src/components/items/TransformationField.tsx`) and marked as a vertex set (`src/lib/marking/transformation.ts`); a wrong drawing is named against the library of single transformations ("That is a reflection in the y-axis. The question asked for a reflection in the line y = x."). A graph common error whose `test` text lists the wrong image's vertices, e.g. "image drawn at (-3, 1), (-8, 1), (-3, 4), the reflection in the y-axis", fires when exactly those vertices are placed; other graph tests are descriptive only. The grid draws the mirror line or centre it can read from the stem ("the line $y = x$", "the line $x = 2$", "about the origin", "centre $(2, 2)$"). Histogram, points-line and curve plots still self-mark.
- Equations are equivalent up to a constant factor (2x + 3y = 7 ≡ 4x + 6y = 14) and, when one side is a formula for a symbol (`x = …`), up to a variable factor as well: x(8 − w) = 12 + 3w is the same relationship as x = (12 + 3w)/(8 − w) because the equation is linear in x and satisfied by the formula (`sampleSolves` in `src/lib/marking/algebra.ts`). With form "subject" that reads "right relationship, x is not the subject yet"; a sign slip in the unrearranged equation is still reported as a sign error. An equation with the right value as one of several solutions (x² = wx/4) stays not-equivalent.
- When a drawn transformation matches a graph common error, the engine's identification leads and the authored diagnosis follows it: "That is a reflection in the y-axis. The question asked for a reflection in the line y = x. <authored feedback>". Write graph feedback as the second sentence of that pair.
- `graph` answers with plot "points-line", "curve" or "histogram" are drawn on a data-scaled grid (`src/components/items/PlotField.tsx`: axes from the table's values, five small squares to a labelled one, taps snap to a small square) and marked element by element (`src/lib/marking/plot.ts`): each table point within the spec's absolute tolerance, one height per histogram bar within `scaleTolerance`, and, when `lineRequired` is true with a two-point `lineThrough`, a line laid with two taps that must pass within tolerance of both points (a line of best fit or a straight-line graph). A `lineThrough` with more than two points, or a curve, means "join the plotted points": the field draws the join once every point is placed and the feedback tells her to draw it smooth on paper. The part's marks are shared in proportion (all of them only when everything is right). A graph common error on one of these parts fires when its `test` text names the misplaced point or points, e.g. "point plotted at (6.4, 12)" or "line through (0, 0) and (10, 20)": every listed point must be among the points she placed (the line's two points count); a test with no coordinates is descriptive only. A `box` plot renders a scale (`src/components/items/BoxPlotField.tsx`): the five values are placed in order by tapping or typed, and each within the absolute `tolerance` is one element of five ("the median should be at 34, not 30"). A `region` plot draws the boundary lines of its `inequalities` (dashed when strict) on squared paper (`src/components/items/RegionField.tsx`); she taps one point inside the region she would shade, the field shades the side of every boundary that point fixes, and the marker (`src/lib/marking/region.ts`) counts each inequality the point satisfies, naming the boundary she is on the wrong side of with a test point ("it needs x + y ≤ 5, and (0, 0) shows which side that is"). Inequalities are read as linear forms such as "x + 2y ≤ 6", "y ≤ x", "y > 2x − 1" (≤ ≥ < > or \le \ge; a point on a line is asked to move). Only best-fit plots still self-mark.
- Equation parts (`src/components/items/equation-marking.ts`): a `$…$`, `\(…\)` or `\[…\]` wrapper around the typed equation is ignored, because the notes print equations as `$\ce{…}$`; the `\ce{…}` wrapper is unwrapped by brace depth, so a charge written `^{3+}` inside it is kept. Brackets in a chemical formula are the formula (Mg(NO3)2 is not MgNO32); only the physics formula path, which multiplies symbols implicitly, drops brackets that merely wrap a symbol.
- Algebraic `form` values for logarithms: `single-log` (exactly one logarithm and it is the whole answer: a coefficient in front or a second log fails as equivalent-wrong-form) and `expanded-logs` (no product, quotient or power inside any logarithm), both checked after equivalence like `y=mx+c`; a `y = …` wrapper and a leading minus are read through. `single-log-expanded` also requires the argument multiplied out (log 8x^3 passes; log (2x)^3 and log(2^3 x^3) fail). A numeric fraction typed before a function is its coefficient ("1/2 log n" is half of log n; "log n / 2" reads as log(n/2), as on paper). A second answer after a number ("4 or −4", "5 and 16") is not a unit: the response is unparseable rather than scoring the first value.
- Relation signs are spaced out and ± is expanded before key words are matched ("x=6 or x=−6" and "x = ±6" both contain the words "6" and "-6"). Even so, a "values of x" answer is better encoded as an algebraic solution set (latex `x=6, x=-6`): the algebra engine parses "or", commas and ± and reports a partial set. A solution value typed with a degree sign or the word "degrees" ("30° and 150°", "x = 150 degrees", "30^\circ") is the bare value, so a trig solution set needs no rescue common error for the sign.
- The CCEA listing rule (`countListedItems`) counts an answer as a list only when every comma, semicolon, slash, "and" or "or" segment is at most four words, and a short segment that opens like a clause continuation ("captured by the leaves", "which", "so", "because", "by", "with" …) is not an item, so "the sun, captured by the leaves" is one answer. Every word of a key-word phrase may take or drop a trailing s ("rabbit number" ~ "rabbits number"). A comma inside brackets is part of the item, so "(4, 0) and (1, 0)" is two answers.
- Method marks (`src/lib/marking/working.ts`, the WorkingLadder): under a numeric, algebraic, equation or mcq part whose scheme carries an M, MA, MW, W or P point, the learner may type her working one line per step (`src/components/topic/WorkingField.tsx`; open by default on exam-style and on `requiresWorking` parts). When the answer is not fully right, each line is matched against the point's own `text` (boilerplate trimmed, each "A or B" alternative separately), its `accept` spellings, the maths inside a prose-worded point, and the worked-solution line that pairs with it, by the step comparer or by algebraic equivalence; each point takes one line and each line is spent once; the recorded marks are the higher of the answer's award and the method marks earned, capped at the part's marks. Write a method point as the line an examiner would tick, one alternative per `accept` entry. A and B points are never paid by the ladder.
- An algebraic answer that is equivalent but in the wrong form (not simplified, not a single logarithm, not factorised: reason `equivalent-wrong-form` or `not-simplified`) keeps every mark but the last on a multi-mark part, so the scheme's working mark is paid without a pack-side common error; a one-mark part pays nothing.
- The constant of integration has one case: "2x⁴ + C" earns a spec written "2x^4 + c" and the other way round; a missing constant still fails.
- Vector answers: an algebraic spec whose `variables` name both `i` and `j` is a vector, and the learner may type `3i + 4j`, `4j + 3i`, bold or hatted unit vectors (`3\mathbf{i} + 4\mathbf{j}`, `3\hat{i}+4\hat{j}`), a two-row `pmatrix`/`bmatrix` column, a plain tuple `(3, 4)`, or the vector followed by a unit (`3i + 4j m/s`); a wrong vector is diagnosed as algebra (a sign error is named). Do not put a typed-form instruction on the answer line. A common error on a vector part fires on every one of those spellings, and a unit after a tuple or a column is read too; the unit itself stays in the prompt text (an algebraic spec has no unit field).
- Matrix answers (`kind: "matrix"`) also read a scalar in front of the matrix, as CCEA prints an inverse: `\frac{1}{5}\begin{pmatrix}…\end{pmatrix}`, `1/5 [[…]]`, `0.5(…)`, `−2(…)`, with or without a times sign; fractions stay exact (2/5 marks against 0.4).
- A paired-answer common error whose pattern is a tuple (`(2, 3)`) fires on every spelling the part accepts, the assignment `p = 2, q = 3` included.
- Common errors run only when the part is not fully correct. `order` parts test text patterns against the arranged item texts ("organ, tissue, organ system"), not the submitted indices.
- Key-word matching also drops currency, percent and degree signs, so "96°" earns a "96" group and "£8106.96" earns "8106.96"; every key-word group should include the phrasing the part's own worked solution uses (`npx tsx scripts/qa/text-parts-vs-solutions.mts` lists the parts where it does not).
- When a numeric spec's unit is "%", a percent sign on the answer is that unit, not a choice of form: "45%" and "45" both pass `acceptForms: ["decimal"]` for a 45% target, and "0.45" is reported as the percent/decimal confusion. Under an accuracy instruction the written number is what is checked ("12%" is 12 to 0 d.p., so it passes a 1 d.p. instruction exactly as "12" does), so a percent part keeps its d.p. tolerance.
- Numeric answers may carry a unit phrase after the number ("36 breaths per minute", "9 mmol/dm³", "-5.5 °C per minute"); units outside the conversion table match the spec's unit by spelling, loosely ("breaths/min" = "breaths per minute"), so a rate part is encoded with the unit in the spec and `unitRequired: false`. A unit phrase may carry unicode superscripts ("0.45 mol dm⁻³", "9.8 m s⁻²"). A one-letter unit counts when a slash, a power or "per" follows it ("0.5 g/s", "2 s⁻¹", "2 s^-1", "0.5 g per s", "0.5 g s⁻¹" all read; a bare letter after a number is a variable).
- A d.p. / s.f. tolerance is a closeness test (1.8, 1.80 and 1.804 are all right for 1.8 to 2 d.p.). Only when the part's stem instructs the accuracy in an instruction sentence ("Give your answer to 2 decimal places", "Round to the nearest penny"; `instructsAccuracy` in `mark.ts`) does it also govern the written form: too many places is wrong, an exact value with the zeros dropped ("150" for 150.00) stays right and gets a write-150.00 reminder. A given such as "6.4 cm, correct to 1 decimal place" is not an instruction. An instruction sentence starts with a command word or attaches the accuracy to "your answer" ("Show your working and give your answer to one decimal place" counts).
- A direction after a numeric answer ("1 m/s² downwards", "5 N to the left", "0.4, directed downwards", "up the slope", "north-east", "anticlockwise") is not read as a unit: the number is marked on its own and the direction is ignored. A part whose stem asks for a direction carries it as its own text or mcq part; the numeric engine never marks a direction.
- In the find-the-mistake fix box a line's value is its last number with unit exponents ignored, so "a = 4 m/s^2" and "a = 4 ms^-2" reach 4; a trailing unit (N, J, W, Pa, m/s, m/s² and the plain ones) is dropped before lines are compared.

## Offline

`scripts/build-sw.mjs` writes `out/sw.js` after `next build`. Install precaches the shell only (every page that is not a single topic or paper, the app assets, manifests and decks, about 10 MB); pages the learner opens are kept as they are fetched. The on-demand set (topic pages and their RSC payloads, the published content JSON, paper pages, about 50 MB) is fetched all at once when the learner taps "Download the full copy" in Settings (`src/lib/offline-copy.ts` posts `offline-copy:start` to the worker, which reports `offline-copy:progress` / `offline-copy:done` and answers `offline-copy:status`). The wish is remembered per device (`localStorage` key `cairn.offline-copy`), and `ServiceWorker.tsx` requests the copy again after each new worker version, because a new version starts from an empty cache. Nothing large is ever downloaded without that tap.

## Content checks

- `npm run content:build` / `content:check` write `public/content/<subject>/<id>.json` in place and delete stale files afterwards, never emptying the folder first: `next build` in the other session copies `public/` while a publish runs, and a wiped folder shipped an export with no lessons (19 Sep).
- `npm run content:check` — strict publish (every bundle must validate), then `scripts/qa/lesson-v2.mjs`, whose template breaches are fatal (unanswered examiner sources stay warnings until the traps pass closes them); prints a `KEYWORDS` line for any text-answer key-word group that no accepted answer can earn. It also fails (INVALID, bundle skipped) on an unexpanded generator placeholder `${…}` in a bundle or note file, on duplicate option texts in one multiple-choice item, on a numeric or algebraic common error the spec would mark correct (it can never fire), and on a numeric value carrying a floating-point artefact (`src/components/items/content-lint.ts`), and on an unpaired "$" in any learner-facing string (hints included) or a maths segment that contains prose words such as "with centre" (the dollars are paired but misplaced). It also fails a text common error whose regex carries a heredoc-halved signature ("[sS]" for [sS], "[^;n]" for [^;
], "b(" for (; `mangledRegexDefect`), which compiles but fires on nothing. It also fails on a figure that draws nothing (a path without d, path data written as text or as bare text inside an element, an SVG with no shape), in bundle figures and in the note's figure blocks (`lintNoteBlocks`); `node scripts/qa/svg-draws.mjs` is the standalone scan of every SVG in the packs.
- `node scripts/qa/lesson-v2.mjs [--unit m3] [--json] [--traps-fatal] [--depth] [--depth-fatal] [--teach] [--teach-fatal] [--prompts] [--prompts-fatal]` — `--teach` lists gates that come before their section explains and shows the idea (teach → show → check, `scripts/qa/teach-show-check.mjs`; the owner's ruling of 24 Sep 2026); `--prompts` lists notes wiring more than two retrieval prompts and prompt answers over 25 words (`scripts/qa/prompt-few.mjs`); both are warnings until their `-fatal` flag. `scripts/qa/frozen-surface.mjs snapshot|check <bundle dir>` is the depth-pass guard (nothing on the marked surface may change). It also checks every note against "Lesson template v2" in `pipeline/prompts/author-topic.md`, and against the "Depth standard (22 Sep 2026)" floor for the note's band (sections, roles, gates, variants, twists, visuals, worked examples, practice rungs, exam-style, find-the-mistake, prompts, diagnostics; label sizes and long maths): one summary line by default, `--depth` for the note-by-note report, `--depth-fatal` to make a shortfall a breach, `--json` rows under `depth` and `depthSummary`. Template v2: hero first with a lede of ≤ 60 words that is not the hook and three verb-led "can" lines, a visual before word 80, every teaching stretch ≤ 120 words between gates, a `why` callout and at most one `examiner` callout in the body, a "You can now" recap before the closing section, an "In the exam" panel that is one heading plus one paragraph of ≤ 80 words and the prompts (≤ 150 words in all, no gate, no spec or examiner callout), the retrieval prompts last, and British English with the instrument exemption (a light meter and a pH meter keep their spelling). Gates that read on their own are delegated to `gate-context.mjs`. Exit 1 on any breach. An examiner source in `topic.examinerSources` that no `sheet.traps` entry answers is printed as a **warning**, because closing one means reading the Chief Examiner report and writing the finding — never inventing a trap to satisfy a checker; `--traps-fatal` promotes them once the Sheets have caught up.
- `node scripts/qa/gate-context.mjs` — lists note gates whose prompt leans on a figure above them (they also appear alone in the review inbox) with the nearest preceding visual; exit 1 when one has none.
- `node scripts/qa/svg-draws.mjs` — decodes every SVG in the packs and reports figures that cannot draw (paths without `d`, path data as bare text, no drawn shape); exit 1 on any finding.
- `node scripts/qa/shingles.mjs` — every 8-word run our content shares with the private corpus, classified: **stock** instruction language, allowed, which means it recurs in three or more different question papers *and* is command material (it overlaps a command word from `packs/*/exam-true/command-words.json` — question stems such as "Which" excluded — or one of the standing exam phrases in the script's `STANDING_PHRASES` (which covers the accuracy and working instructions, "the diagram shows", "the table shows", "not drawn to scale", "in order of size", "starting with the smallest", "mark on the diagram", "all the forces acting" and the QWC sentence), or it sits inside a formula-sheet line); **stimulus-copy**, a run that recurs in three or more papers but carries no instruction language, which is the board's reused context prose and is a breach however often it is reused (unless it lies inside a standard statement of a named theorem, law or definition listed with its reason in `scripts/qa/shingles.allow.json` — a circle theorem has one accepted English form — which is reported as **allowed**); **paper-copy**, a run from only one or two papers, which is a copy of that question's own wording; and **scheme-or-report**, a run shared with any mark scheme or Chief Examiner report, never allowed. `--unit` / `--topic` / `--json`, exit 1 on any breach, and nothing from the corpus is printed but the shared run itself.
- The strict build also prints a `FIGURE` warning for every question figure whose text nodes, `<title>`, `<desc>`, aria-label, alt or caption carry a phrase one of its parts asks the learner to give (key words, short accepted answers, the correct option, label targets; letter labels such as "tube C" exempt), counted in the summary line (`figureLeakWarnings` in `src/components/items/content-lint.ts`). Authors keep the annotated figure for the note and an unannotated, lettered copy for the question.
- `node scripts/qa/figure-leaks.mjs` — the standalone, gating version of that warning, over every bundle under `packs/*/content`: it reads each figure's text nodes and all of its accessible text (`<title>`, `<desc>`, aria-label, and an image figure's `alt`/`caption`) and tests it against that part's accepted spellings, every key-word group's `any` list, label targets, `order`/`steps`/`table` answers, a numeric answer's own value, the correct mcq option and a text-long QWC's indicative points — and it sweeps diagnostics, worked-example twins, find-the-mistake items and retrieval prompts, which the build's warning does not reach. It splits what it finds: a **LEAK** is a figure that *names* the answer (a text node, title or alt segment that IS the accepted answer, an option, a label target, a pathway item or a printed value, or a key word where the part asks her to name or label the thing) and exits 1; a **REVIEW** line is a shared word that is not handed over (a key word inside a sentence, or a name on a figure whose whole job is to name things — a food web has to name its organisms) and never gates. A phrase the part's own stem already uses is never a leak. A worked example's own figure is checked against the steps its faded versions hide and against the final answer for the problem version (`WE-LEAK` lines, warnings until `--we-fatal`; `scripts/qa/we-hidden-steps.mjs` mirrors `fade.ts`); the twin's figure is checked against the twin's answer. The build's `FIGURE` warning matches one text node, title or alt at a time (two labels in separate nodes are never one phrase) and applies the same faded/problem rule to worked examples. `--unit` (repeatable), `--subject`, `--json`, `--quiet`.
- `npx tsx scripts/keyword-soft.mts` — lists the soft key-word findings the build only counts (groups earned only by the part's own wording), with the part id.
- `npx tsx scripts/qa/text-parts-vs-solutions.mts` — marks every text part of 2+ marks with its own worked solution as the answer and writes docs/dev/qa/text-parts-vs-worked-solutions.md listing the parts whose key words do not cover their solution's phrasing (the marker would under-award a learner who wrote those words); the brief's rule is "key words must cover the worked solution".
- `node scripts/qa/crawl-export.mjs` — renders every topic page of the export on :3200 and reports console errors, KaTeX errors, leaked "$" text, broken images and self-marked parts (docs/dev/qa/crawl-export.md).
- `npm run insights:unregistered` / `insights:build` / `insights:validate` — misconception registry round trip (source modules in `pipeline/mine/insights-source/`).
- `node pipeline/mine/extract-cer.mjs` — rebuilds the private Chief Examiner report blocks; Unit 7 Booklet A reports yield one `Q1` block per discipline and tier.

## Data rule: reads only inside a liveQuery

Dexie forbids a write inside a `liveQuery`/`useLiveQuery` querier and throws `ReadOnlyError` ("Readwrite transaction in liveQuery context"); a querier wrapped in try/catch then silently returns its fallback (the companion went silent everywhere this way on 19 Sep 2026). Queriers read; seeding, upserts and "touch" writes go in an effect or an event handler. `src/lib/companion/live.test.ts` shows the pattern and the regression test.
