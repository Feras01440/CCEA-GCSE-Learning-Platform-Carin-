### F8 [moderate] `q…0012/b` and `q…0003/main`: the wall-moves common error mis-diagnoses correct answers

Current patterns:

- `q…0012/b`: `wall[^;\n]*(pulls|pulled|moves|moved|comes|came) away`
- `q…0003/main`: `wall[^;\n]*(pulls|moves|comes) away`

`[^;\n]*` crosses commas and full stops, so the pattern fires on answers in which the **membrane** is
the thing that moves (verified `true`): "The cell wall does not move, but the membrane has moved away
from it." and "The cell wall stays where it is, and the membrane comes away from it." The learner is
then told "The rigid wall stays put; it is the membrane that comes away from it" — the very thing they
wrote. (The q.0003 pattern also misses the real error when it is written "The wall **has pulled** away
from the membrane", because it lacks the past forms.)

**Fix** — one pattern for both parts, requiring the wall to be the subject of the verb (verified: false
on four correct answers, true on four genuine wall-moves answers including the past forms):

```
\bwall\b[^;,\n]{0,8}\b(pulls|pulled|moves|moved|comes|came)\s+away
```

### F12 [minor] `q…0006/main` and `q…0011/c`: the stem demands a unit the spec does not carry, and typing it is unreadable

1. `AnswerField.unitSuffix` only shows a unit chip when `spec.unit` is set, so the field gives the

**Fix** — engine side: add `⁻` (and `⁺`) to both character classes of `UNKNOWN_UNIT_RE`. Do **not**
"fix" it in the bundle by adding `"unit": "mol dm⁻³"`: verified that this still cannot read the
superscript form *and* newly rejects `"0.45 mol/dm3"` and `"0.45 moldm-3"` as a wrong unit.

## 3. Cross-cutting (engine, `src/lib/marking/numeric.ts` — affects 6 parts in these two bundles)

### X1 [moderate] A percentage typed as a whole number with a `%` sign is rejected, while the same number without the sign is accepted

On every part whose spec is `unit: "%"` with `tolerance {"type":"dp","places":1}` and a stem that says
"Give your answer to one decimal place" — `q…osmosis.0005/main`, `q…osmosis.0011/b`,
`we…osmosis.01` twin, `q…transpiration.0005/main`, `q…transpiration.0009/a`,
`q…transpiration.0014/c` — the probe gives:

| typed | marks |
|---|---|
| `8` | 2/2 (accepted, with the "write 8.0 on the paper" note) |
| `8.0` | 2/2 |
| `8.0%` | 2/2 |
| `8.0 %` | 2/2 |
| `8%` | **0/2** — "Give the answer to 1 decimal place: 8.0." |
| `8 %` | **0/2** — same |

Cause: for a percent-form answer `parsed.value` is the fraction (0.08) while `target.value` is 8, and
`checkAccuracy` compares those two raw values rather than the unit-reconciled value:

```ts
// numeric.ts, checkAccuracy (~line 1670)
if (!nearlyEqual(parsed.value, target.value, 1e-12)) {
  return verdict(parsed, "wrong-accuracy", `Give the answer to ${plural(requiredDp, "decimal place")}: ${expected}.`, { correct: false });
}
```

`droppedZerosNote` (~line 1647) has the same comparison, which is why the reminder is not reached either.

**Fix** — pass the reconciled value (`aVal` from `reconcileUnits`) into `checkAccuracy` and
`droppedZerosNote` and compare with that, so `8%` behaves exactly like `8`. No bundle change is needed
or appropriate. (Flagged rather than edited: `src/` is outside this pass.)
